## 🧠 What I'm curious about: how a full-stack app stays safe end to end

Every layer of an application is a place where things can go wrong. This is the map I keep in mind while building and learning:

| Layer | What can go wrong | How I defend against it |
|---|---|---|
| **Frontend** | XSS, leaking secrets in client code | Output encoding, no secrets in the browser |
| **API** | Broken access control, injection, abuse | Server-side permission checks, input validation, rate limiting |
| **Authentication** | Weak sessions, stolen tokens | Hashed passwords, short-lived tokens, least privilege |
| **Database** | NoSQL/SQL injection, over-exposed data | Validated queries, scoped access, no public DB endpoints |
| **Network** | Open ports, exposed services | Regular scanning (Nmap), closing what isn't needed |
| **Deployment** | Leaked keys, misconfiguration | Environment variables, HTTPS, minimal exposure |

Core rule I follow: **never trust the client. Validate everything on the server.**
